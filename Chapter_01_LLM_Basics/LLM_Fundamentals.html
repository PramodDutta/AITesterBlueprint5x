Words made simple

97 AI words you will hear at work, each explained three ways: in plain words, with an everyday comparison, and what it means for a tester. New here? Choose Start here for the 25 words to learn first.

Agent loopBuilding with it

In plain wordsThe cycle an agent repeats: think about the next step, act by calling a tool, observe the result, and decide again.

Think of it likeTry, look, adjust, try again.
For a testerEvery loop needs stop rules: a step limit, a cost limit and a human check before risky actions.
Learn it in lesson 11: What is an AI agent? →
AI agentStart hereBuilding with it

In plain wordsA system where a model works toward a goal by choosing actions (tool calls) in a loop until it is done.

Think of it likeAn intern given a goal and a set of tools, rather than one question.
For a testerJudge agents by what they did: tool calls, final system state, steps and cost. Not by what they say.
Learn it in lesson 11: What is an AI agent? →
AI appAlso: chatbot, AI assistantThe basics

In plain wordsThe product you use, such as ChatGPT, Claude.ai or a company bot. It wraps a model with a screen, history, safety checks and tools.

Think of it likeThe car around the engine: dashboard, seatbelts, doors.
For a testerBugs can live in the app, not the model: wrong history sent, a missing document, a broken tool. Test the whole path.
Learn it in lesson 01: AI, ML and LLMs in plain words →
APIAlso: application programming interfaceTalking to it

In plain wordsA way for programs to talk to each other. You call a model through its API by sending a request and reading the response.

Think of it likeA restaurant's order window: a set way to ask and receive.
For a testerTest model APIs like any API: auth errors, rate limits, timeouts, and every field your code reads.
Learn it in lesson 10: Tools and MCP: giving the model hands →
API keyTalking to it

In plain wordsA secret password that identifies who is calling an API, and who pays for it.

Think of it likeA company credit card for the model.
For a testerNever put API keys in prompts, logs, screenshots or Git. Test that error messages do not leak them.
Learn it in lesson 13: How a tester checks LLM output →
Artificial intelligence (AI)Start hereThe basics

In plain wordsComputers doing tasks that normally need human thinking: understanding language, recognising images, making decisions.

Think of it likeA big umbrella word. Machine learning, deep learning and LLMs all live under it.
For a testerWhen someone says "AI feature", ask which kind: a rule engine, a prediction model or an LLM. Each is tested differently.

AttentionHow it works

In plain wordsThe part of a transformer that lets each word look at the other words and decide which ones matter for its meaning.

Think of it likeA highlighter: in "it was too big", attention highlights which earlier word "it" refers to.
For a testerEvery word in a prompt competes for attention. Remove noise, and put the important rule where it is easy to find.

Base modelAlso: pretrained modelStart hereThe basics

In plain wordsA model straight after pretraining. It is great at continuing text but does not follow instructions well.

Think of it likeA student who has read every book but never had a job: knows a lot, does not take orders.
For a testerIf a model rambles or continues your prompt instead of answering it, you may be calling a base model by mistake.

BenchmarkAlso: leaderboardTesting it

In plain wordsA public test set used to compare models. Useful for a shortlist, but it is not your task.

Think of it likeA car's official mileage figure versus your real daily commute.
For a testerPick models with your own golden dataset. Public benchmarks can be memorised by the models.

BiasAlso: fairnessTesting it

In plain wordsUnfair differences in a model's answers for similar inputs, for example depending on a name, gender or language.

Think of it likeA judge who is harsher on some people for no good reason.
For a testerChange only one detail, such as the name, and compare the answers. They should match.

Chain of thoughtAlso: CoT, think step by stepTalking to it

In plain wordsAsking a model to work through a problem step by step before answering. Reasoning models now do this by themselves.

Think of it like"Show your working" in a maths exam.
For a testerThe written steps may not be how the model really decided. Check the final answer, not the story.

Chat historyAlso: conversation historyTalking to it

In plain wordsThe earlier messages of a chat, which the app sends again with every new message so the model can follow the conversation.

Think of it likeThe minutes of earlier meetings, handed over each time.
For a testerLong histories cost more tokens on every turn, and eventually get cut. Test long chats.

Chat modelAlso: instruct model, assistant modelStart hereThe basics

In plain wordsA base model that was fine-tuned to follow instructions and hold a helpful conversation. The models inside ChatGPT and Claude are chat models.

Think of it likeThe same student after job training: follows instructions, answers politely.
For a testerChat models are trained to please people, so they can agree too easily (sycophancy). Ask neutral questions.

ChunkAlso: chunkingBuilding with it

In plain wordsA small piece of a document, usually a few paragraphs, stored and searched on its own.

Think of it likeIndex cards cut from a long document.
For a testerRules split across two chunks are often half-found. Test questions whose answer is split across two chunks.

ContextTalking to it

In plain wordsEverything the model can see for one reply: system prompt, chat history, documents, tool results and your question.

Think of it likeEverything on the desk while the model works.
For a testerIf the right information is not in the context, the model cannot use it. Inspect what was actually sent.

Context engineeringTalking to it

In plain wordsChoosing what goes into the context window: the right documents, a short history, clear rules, and nothing that distracts.

Think of it likePacking a small suitcase well.
For a testerLess but better context often beats more. Compare answers with the full document and with only the relevant section.
Learn it in lesson 07: What is a context window? →
Context windowAlso: context length, context limitStart hereTalking to it

In plain wordsThe maximum amount of text a model can handle in one request, counted in tokens. It includes the answer.

Think of it likeThe size of the desk: everything must fit on it at once.
For a testerTest inputs just under and just over the limit, and check what the app does: error, cut or summarise.

In plain wordsMachine learning that uses very large neural networks with many layers. LLMs, image generators and speech recognition all use it.

Think of it likeMachine learning with a much bigger brain.
For a testerDeep learning models cannot explain their decisions line by line, so you judge them by their outputs.

EmbeddingBuilding with it

In plain wordsA list of numbers that captures the meaning of a piece of text. Texts with similar meaning get similar numbers.

Think of it likeCoordinates on a meaning map: "login" and "sign in" are neighbours.
For a testerEmbeddings match meaning, not exact words, so test with synonyms, typos and other languages.

In plain wordsTesting AI output against agreed criteria, usually over many examples, to get a score you can compare over time.

Think of it likeA regression suite, scored instead of pass or fail.
For a testerRun your evals after every change to the prompt, model or documents, like any regression suite.

In plain wordsExtra training on a smaller, focused set of examples, to teach a model a task or a style.

Think of it likeOn-the-job training after school.
For a testerA fine-tuned model must be re-tested on cases it did not train on. It can get worse at things it used to do.

Think of it likeThe kitchen (GPU) and the counter space (VRAM): a big recipe needs a big counter.
For a testerAn 8B model needs about 5 GB when its numbers are compressed to 4 bits each. If a local model is slow or will not load, check memory first.

AI, ML and LLMs in plain words

Where an LLM fits, and what it is not.

New words in this lesson
Artificial intelligence (AI)
Computers doing tasks that normally need human thinking.

Start with the family

People say "AI" for many different things. It is easier when you see them as boxes inside boxes.

A spam filter is AI and machine learning, but it does not create anything, so it is not generative AI. An image generator is generative AI, but what it makes is pictures, not text, so it is not an LLM. An LLM is both: deep learning that generates text. Many newer models are also multimodal: they can read images, screenshots or audio as well as text.

Rules vs learning

Classic software follows rules a developer wrote. Machine learning finds the rules itself, from examples. That one change is why AI features need a different kind of testing.

QuestionClassic softwareAn LLM feature
How is it built?A developer writes every rule: "lock after 5 wrong passwords".It learned patterns from a huge amount of text.
Same input twice?Same output, every time.Often a different output.
How does it fail?A crash, an error, a wrong value.A fluent, confident answer that is wrong.
How do you test it?Check the exact result.Check what must be true, over many runs.

The model and the app are two different things

ChatGPT, Claude.ai and the Gemini app are apps. Inside each app is a model from a model family: GPT, Claude or Gemini. The model does only one thing: text in, text out. The app adds everything else: the chat screen, your history, safety checks, file uploads and web search.

For testers
When an AI feature gives a wrong answer, the bug can be in three places: what the app sent to the model, what the model wrote, or what the app did with the reply. Check all three before you blame the model.

What an LLM is not

  • Not a search engine. It does not look anything up, unless the app gives it a search tool.
  • Not a database. There is no table of facts inside; its knowledge is spread across billions of learned numbers.
  • Not a calculator. It predicts text, so it can get maths wrong.
  • Not up to date. It knows nothing after its training ended, and nothing about your private product unless the app gives it the text.
Think of it like a brilliant intern
An LLM is like a very well-read intern: fast, fluent and confident. But it cannot check its own facts unless you give it a way to check: the source document, a tool, a test.
Remember
  • AI contains machine learning, which contains deep learning, which contains LLMs. Generative AI is any AI that creates new content.
  • The model only turns text into text. The app around it does the rest.
  • Test the whole path: what was sent, what came back, what the app did with it.

How does an LLM work?

One simple loop: guess the next piece of text, again and again.

Autocomplete, at a huge scale

When you type on your phone, the keyboard suggests the next word. An LLM does the same thing. The difference is scale: it learned from a huge library of text, so its guesses are very good. It writes a whole answer by guessing one small piece (a token, lesson 03) at a time.

Each guess is one trip around the loop. That is why answers appear on screen word by word: the model is writing them in real time, and the app shows each piece as it arrives (this is called streaming).

Exactly how the model picks "mat"

Take the sentence "The cat will sit on the ___". The model gives every possible next token a score: higher means "fits better here". Then it turns the scores into chances in three small steps:

  1. Make every score positive with escore (e is a fixed number, about 2.718). Bigger scores become much bigger.
  2. Add them all up to get a total.
  3. Divide each one by the total. Now every candidate has a share, and the shares add up to 100%.

Likely is not the same as true
"mat" wins because it is the most common pattern in the training text, not because the model checked where your cat is sitting. The same happens with facts: "The account locks after 3 attempts" can be the most likely sentence and still be wrong for your product.

Foundation, base and chat models

From a library to a chat model

Pretraining. The model reads trillions of tokens of books, websites and code. It practises one thing: hide the next token, guess it, check the real one, adjust its knobs a tiny bit. This repeats billions of times and takes months on thousands of computer chips (GPUs).

The result is a base model. It knows language and a lot about the world, but it only continues text. Ask it a question and it may continue with more questions, because that is what it saw in documents.

Fine-tuning then turns it into an assistant. First, thousands of example conversations show it how a good answer looks (this is called instruction tuning). Then people rate pairs of answers, and the model learns to prefer the better ones (this is called RLHF: reinforcement learning from human feedback). The result is a chat model, like the ones inside ChatGPT or Claude.

So what is a foundation model?

A foundation model is a large, general-purpose model that many different products are built on, like one foundation under many houses. GPT, Claude, Gemini and Llama are foundation models. Your company's "QA bot" is almost never a brand-new model: it is an app built on top of one of these.

Two more words you will hear. Open-weight models (Llama, Qwen, DeepSeek) can be downloaded and run on your own computers; closed models (Claude, GPT, Gemini) are used over the internet, through the maker's service. Small language models have a few billion parameters: cheaper and faster, good enough for simple, narrow tasks.

Parameters: the knobs

"8B" means 8 billion parameters. More parameters can hold more patterns, so bigger models are often smarter, slower and more expensive. But size alone never proves a model is right for your task: you still test it on your own examples.

Training vs using

The big training happens before you ever use the model, at the AI company. (A team can also fine-tune a model on its own data, but that is a separate, planned project, not something a chat does.) Everything you do in a chat is inference: the knobs are frozen. If you tell a chatbot "our lockout is 5 attempts, not 3", it agrees, but the model has not changed. In a new chat it may say 3 again.

Training also has an end date, the knowledge cutoff. The model knows nothing that happened after its training data was collected, and nothing about your private product unless the app gives it the text.

For testers
Training explains behaviour you will meet in testing: rambling and pattern-copying (base-model habits), polite answers that agree too easily (fine-tuning habits, called sycophancy, lesson 12) and outdated answers (the knowledge cutoff).
Remember
  • Pretraining makes a base model; fine-tuning makes a chat model.
  • A foundation model is the big general model that many products build on.
  • Your chats are inference: they never change the model's parameters.

A chat is a list of messages

A chat looks like a conversation, but to the model it is a list. Each message has a role: system (the app's rules), user (you) or assistant (the model).

Every time you press send, the app sends the whole list: the system prompt, all earlier messages and your new one. The model reads all of it and writes the next assistant message. Nothing else reaches the model.

A good prompt has parts

A model cannot read your mind. Every detail you leave out, it fills with a guess. The Testing Academy's RICE-POT checklist makes sure you leave fewer gaps:

Weak promptWhat the model has to guess
"Write tests for the login page."Which rules? How many tests? Positive or negative? Which format? Can it invent rules? Everything.

The same request written with RICE-POT:

Role: You are a senior QA engineer.
Instructions: Write test cases for the login story below.
  [Mandatory] Cover every rule, R1 to R4.
  [Don't] Invent rules that are not in the story.
Context:
  R1: Lock the account after 5 wrong passwords in a row.
  R2: The lock lasts 15 minutes.
  R3: A successful login resets the counter.
  R4: Wrong credentials show a generic error message.
Example: TC-01 | Lock after 5 wrong passwords | enter a wrong password 5 times | the account is locked | R1
Parameters: At most 10 tests. Only facts from the story.
Output: A Markdown table with ID, Title, Steps, Expected, Rule.
Tone: Clear and short.

Markdown, in the Output line, is a simple plain-text way to write tables and headings. Most AI tools display it neatly.

Zero-shot and few-shot

Zero-shot means you give no examples. Few-shot means you show one to three examples of the output you want. Examples are one of the strongest signals in a prompt: the model copies their format and style, including their mistakes. So make your examples correct.

Chain of thought means asking the model to "think step by step" before it answers. It helps on multi-step problems. Newer reasoning models do this by themselves (lesson 02).

For testers
Treat a prompt like test code: keep it in version control, review changes, and re-run your checks after every edit. Changing one sentence can change every answer.
Remember
  • The model only sees the list of messages the app sends: system, user and assistant.
  • Every gap in your prompt becomes a guess. RICE-POT closes the gaps.
  • Examples are powerful: the model copies them, mistakes included.

Picking the next token

After the model scores the candidates (lesson 02), something must pick one. It does not always take the top one. It rolls a weighted dice: "mat" has about 62 chances in 100, "floor" about 14, and so on. This is called sampling, and it is why the same question can get a different answer.

Temperature reshapes the dice

Low temperature makes the top choice even stronger: focused and repeatable. High temperature evens the chances out: more variety, more odd picks. At temperature 0, the model simply takes the top token every time (greedy).

The exact maths is one small change to lesson 02: divide every score by the temperature before the escore step. At 0.5, the gaps between scores double and "mat" jumps to 92%. At 2, the gaps halve and "mat" falls to 34%.

RAG: giving the model your documents

Closed book vs open book

Without help, a model answers from what it learned in training. It has never seen your PRDs, your wiki or last week's release notes, so it guesses. RAG fixes that: before the model answers, the app finds the relevant pages and puts them into the prompt. It turns a closed-book exam into an open-book one.

The three steps

  1. Retrieve: search your documents for the chunks that best match the question.
  2. Augment: add those chunks to the prompt, with an instruction like "answer only from these sources".
  3. Generate: the model writes the answer, ideally pointing to the source it used.

How the search finds meaning

Before any question arrives, the documents are cut into chunks, and each chunk gets an embedding: a list of numbers that places it on a "meaning map". The question gets an embedding too. The search returns the chunks that sit closest to the question.

This is called semantic search: searching by meaning. It is why a question about "signing in" can find a document that only says "login". Many systems also mix in normal keyword search, because exact words like error codes and IDs matter too.

Why models make things up

A hallucination is a fluent, confident answer that is not supported by facts or by the sources the model was given. It is not a rare glitch. The model always writes a likely-sounding next token (lesson 02), and research from OpenAI in 2025 adds a reason: training and tests mostly reward right answers and give nothing for "I don't know", so guessing scores better than admitting it.

Same question, different answers

Because of sampling (lesson 06), and because servers process many requests together, the same prompt can give different answers. This is non-determinism. One good run proves little; measure how often it is right (lesson 13).

It agrees with you too easily

Chat models are trained on what people rate highly, and people like being agreed with. So "This is a bug, right?" tends to get "Yes!" This is sycophancy.
